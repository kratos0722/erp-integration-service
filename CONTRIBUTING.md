# Contributing

Thanks for your interest in improving this project.

## Workflow

1. Create a branch from `main` (`feat/...`, `fix/...`, `chore/...`).
2. Make your change with tests.
3. Ensure the build and tests pass locally.
4. Open a pull request using the template; link any related issue.
5. A review is required before merge; keep PRs small and focused.

## Commit messages

Use clear, imperative messages (e.g. `fix: reject invalid invoice status`).
Group related changes; avoid unrelated churn in the same PR.

## Code style

- Keep changes consistent with the surrounding code.
- Add or update tests for any behavior change.
- Update the `README` when public behavior changes.
